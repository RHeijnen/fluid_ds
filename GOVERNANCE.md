# Governance

Fluid is maintained in public. Technical decisions, component proposals, and
breaking changes are reviewed through issues and pull requests in the project
repository.

Maintainers are responsible for release approval, security response, maturity
promotion, and enforcement of the support policy. Contributors may propose a
component for promotion from experimental to beta or stable by showing that its
quality record satisfies the current certification gate.

Every release must include generated quality and maturity reports, relevant
changesets, migration notes for breaking changes, and a green verification run.
No single documentation badge can promote a component: `quality/maturity.json`
is the versioned source of truth used by reports and Storybook drift checks.

Project discussions should be respectful, technically grounded, and recorded in
the repository so decisions remain discoverable.
