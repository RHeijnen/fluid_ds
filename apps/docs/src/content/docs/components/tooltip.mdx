`<fluid-tooltip>` is the small contextual hint, visible on hover or focus of
its slotted child, dismissed when the pointer leaves or focus moves on.
Positioning is handled by Fluid's own engine, so it auto-flips when it would
overflow the viewport, and the popover renders in the top layer so no ancestor
can clip it. Use it for **short, supplementary** text; for anything more
substantial, reach for [`<fluid-popover>`](/components/popover/).

Every tooltip on this page is live. Hover a trigger, or <kbd>Tab</kbd> to it,
to see the real thing.

<Demo>
  <fluid-tooltip content="Save your changes (⌘S)">
    <fluid-button>Save</fluid-button>
  </fluid-tooltip>
  <fluid-tooltip content="More options" placement="bottom">
    <fluid-button variant="ghost" aria-label="More options">
      <fluid-icon name="ellipsis"></fluid-icon>
    </fluid-button>
  </fluid-tooltip>
  <fluid-tooltip placement="right">
    <fluid-button variant="secondary">Rich hint</fluid-button>
    <div slot="content">
      <strong>Pro tip</strong>
      <br />
      Hold Shift to skip the confirmation.
    </div>
  </fluid-tooltip>
</Demo>

### Rich content

Slot anything into the `content` slot for a richer hint. It overrides the
`content` attribute. Keep it short and non-interactive: the popover sets
`pointer-events: none`, so a link or button inside it can never be clicked.

### Delays

`show-delay` and `hide-delay` (both in ms) stop tooltips flashing while the
pointer sweeps across a toolbar. `show-delay` defaults to 100, `hide-delay` to 0. Sweep the pointer across the three buttons below to feel the difference.

<Demo>
  <fluid-tooltip content="Opens instantly" show-delay="0">
    <fluid-button variant="secondary">show-delay 0</fluid-button>
  </fluid-tooltip>
  <fluid-tooltip content="Opens after the default 100ms">
    <fluid-button variant="secondary">default</fluid-button>
  </fluid-tooltip>
  <fluid-tooltip content="Waits 700ms, then lingers for 500ms" show-delay="700" hide-delay="500">
    <fluid-button variant="secondary">slow in, slow out</fluid-button>
  </fluid-tooltip>
</Demo>

```html

<fluid-tooltip content="Deliberate" show-delay="700" hide-delay="500">…</fluid-tooltip>
```

### Disabled

`disabled` turns the tooltip off without unwrapping the trigger, handy when the
hint only applies in some states. The anchor keeps working; only the hint stops.
Hover both buttons: the first one explains itself, the second stays quiet.

<Demo>
  <fluid-tooltip content="This hint is active">
    <fluid-button variant="secondary">Enabled tooltip</fluid-button>
  </fluid-tooltip>
  <fluid-tooltip content="You will never see this" disabled>
    <fluid-button variant="secondary">Disabled tooltip</fluid-button>
  </fluid-tooltip>
</Demo>

```html
<fluid-tooltip content="Only while the draft is unsaved" disabled>
  <fluid-button variant="secondary">Publish</fluid-button>
</fluid-tooltip>
```

### Programmatic open

`open` pins the tooltip visible and keeps it there until you set it back to
`false`; hover and focus are ignored while it is pinned, and <kbd>Escape</kbd>
will not dismiss it. Use it for an onboarding hint you control, not for
ordinary hover text. Click the button to pin and unpin the real tooltip:

<Demo>
  <fluid-tooltip id="tooltip-pinned" content="Pinned open until you toggle it back" placement="top">
    <fluid-button variant="secondary">Anchor</fluid-button>
  </fluid-tooltip>
  <fluid-button onclick="const t = document.getElementById('tooltip-pinned'); t.open = !t.open; this.textContent = t.open ? 'Unpin the tooltip' : 'Pin the tooltip';">
    Pin the tooltip
  </fluid-button>
</Demo>

```ts
const tip = document.querySelector("fluid-tooltip");
tip.open = true; // forced visible
tip.open = false; // back to hover/focus
```

## Listening for show and hide

`<fluid-tooltip>` fires **`fluid-show`** when the hint becomes visible and
**`fluid-hide`** when it is dismissed (pointer out, blur, <kbd>Escape</kbd>, or
`open = false`). Neither carries a payload; the target tells you which tooltip
it was. Use them for analytics on which hints people actually read, or to
lazy-load the content of an expensive hint.

<Tabs syncKey="framework">
  <TabItem label="HTML">
    ```html
    <fluid-tooltip id="tip" content="Save your changes">
      <fluid-button>Save</fluid-button>
    </fluid-tooltip>

    <script type="module">
      document.getElementById("tip").addEventListener("fluid-show", (e) => {
        console.log("shown", e.target.content);
      });
    </script>
    ```

  </TabItem>
  <TabItem label="React">
    ```tsx title="SaveHint.tsx"
    import { useRef, useEffect } from "react";
    import "@fluid-ds/components/define/tooltip";

    export function SaveHint() {
      const ref = useRef<HTMLElement>(null);
      useEffect(() => {
        const el = ref.current!;
        const onShow = () => console.log("shown");
        el.addEventListener("fluid-show", onShow);
        return () => el.removeEventListener("fluid-show", onShow);
      }, []);
      return (
        <fluid-tooltip ref={ref} content="Save your changes">
          <fluid-button>Save</fluid-button>
        </fluid-tooltip>
      );
    }
    ```

    <Aside type="note">
      `fluid-show` is a custom event, so React 18 needs `ref + addEventListener`
      (above); React 19 supports `onfluidShow`. See the
      [framework guide](/guides/frameworks/#react).
    </Aside>

  </TabItem>
  <TabItem label="Vue">
    ```vue title="SaveHint.vue"
    <script setup lang="ts">
    import "@fluid-ds/components/define/tooltip";
    const onShow = () => console.log("shown");
    </script>

    <template>
      <fluid-tooltip content="Save your changes" @fluid-show="onShow">
        <fluid-button>Save</fluid-button>
      </fluid-tooltip>
    </template>
    ```

  </TabItem>
  <TabItem label="Angular">

## Theming

Every styled property reads a **component-scoped `--fluid-tooltip-*` token that
falls back to a main semantic var** (the override ladder), so you get three
levels for free: override the main var to reskin the brand, the
`--fluid-tooltip-*` token to change every tooltip, or the same token on one
instance to change just that one. The **complete list** is in the
[API table below](#api); the ones you'll reach for most are
`--fluid-tooltip-bg`, `--fluid-tooltip-color`, and `--fluid-tooltip-max-width`.

```css title="brand.css"
/* Every tooltip under a brand wrapper. */
[data-fluid-brand="custom"] {
  --fluid-tooltip-bg: var(--fluid-color-neutral-900);
  --fluid-tooltip-color: var(--fluid-color-white);
  --fluid-tooltip-radius: 8px;
}

/* One tooltip that needs more room for a longer hint. */
[data-fluid-id="shortcut-hint"] {
  --fluid-tooltip-max-width: 24rem;
}
```

<Aside type="tip">
  The [Theme builder](/playground/) lets you select a tooltip and tweak these tokens visually, then
  exports the CSS.
</Aside>

### Beyond tokens: `::part()`

The floating element is [`part="popover"`](#api) (and `part="base"` wraps the
trigger). Reach them with
[`::part()`](https://developer.mozilla.org/en-US/docs/Web/CSS/::part) for CSS
not covered by a token:

```css
/* A light tooltip with a hairline border, no new tokens needed. */
fluid-tooltip.light::part(popover) {
  border: 1px solid var(--fluid-border-default);
}
```

## When to use

- A short hint that explains an icon-only button or supplements a terse label.
- Surfacing a keyboard shortcut next to the control it triggers.
- Spelling out a truncated value the layout had to cut short.

### When _not_ to use

- **Critical information**: touch-only users can't hover, and screen readers
  announce tooltips inconsistently. Put it in the visible copy instead.
- **Anything interactive** (a link, a button, a form field): the popover sets
  `pointer-events: none`, so nothing inside it is clickable. Use
  [`<fluid-popover>`](/components/popover/).
- **A list of actions**: use [`<fluid-dropdown>`](/components/dropdown/).
- **A persistent marker** on a row or card: use
  [`<fluid-badge>`](/components/badge/) or [`<fluid-tag>`](/components/tag/).

## Accessibility

The cross-component contract is in the
[Accessibility guide](/guides/accessibility/); the notes below are
tooltip-specific (WAI-ARIA tooltip pattern).

### Names & roles

- The popover is `role="tooltip"`; the slotted trigger gets `aria-describedby`
  pointing at it, so the text is announced after the trigger's accessible name
  ([SC 4.1.2](https://www.w3.org/WAI/WCAG22/Understanding/name-role-value)).

### Keyboard & pointer (SC 1.4.13)

- Shows on **hover and focus**, so keyboard users see it on <kbd>Tab</kbd>.
- <kbd>Escape</kbd> dismisses it (dismissible). A tooltip pinned with `open` ignores Escape, which
  is why `open` is for hints you control, not hover text.
- It stays visible while hovered and doesn't steal pointer events
  (`pointer-events: none`), satisfying
  [SC 1.4.13 Content on Hover or Focus](https://www.w3.org/WAI/WCAG22/Understanding/content-on-hover-or-focus).

### Don't hide essential info here

A tooltip is supplementary, the trigger must still make sense on its own, and
never put the only copy of critical information (or any interactive control)
inside one.

### Motion

The fade honors `prefers-reduced-motion`.
