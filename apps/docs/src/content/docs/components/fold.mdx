`<fluid-fold>` is a fold line: a horizontal rule with a "Show more" control in
the middle of it. Where an accordion announces a section by heading, the fold
is the opposite gesture. The page above it reads complete on its own, the line
reads as its natural end, and the label says there is more underneath for
whoever wants it: device attributes, raw identifiers, a row of secondary
charts.

<Demo>
  <div style="width: 100%;">
    <p style="margin: 0 0 var(--fluid-space-3);">The part of the page everyone needs.</p>
    <fluid-fold label="Show more" open-label="Show less">
      <p style="margin: var(--fluid-space-3) 0 0; color: var(--fluid-text-secondary);">
        The details a reader only sometimes needs, folded away until asked for.
      </p>
    </fluid-fold>
  </div>
</Demo>

### Its own label, open and closed

The toggle says `label` while folded. Give it `open-label` and it changes its
mind once open; omit it and the label stays put.

### Listening for the toggle

```ts
const fold = document.querySelector("fluid-fold");
fold.addEventListener("fluid-toggle", (event) => {
  console.log(event.detail.open ? "unfolded" : "folded");
});
```

## When to use

- The long tail of a detail page: attributes, identifiers, diagnostics that
  belong on the page but not in everyone's way.
- A row of secondary panels (charts, summaries) beneath the content that
  answers most visits on its own.

If the hidden content is one of several labelled sections, reach for
[`<fluid-accordion>`](/components/accordion/) instead: a fold has no heading,
so two folds in a row read as two identical lines. If nothing needs hiding,
[`<fluid-divider>`](/components/divider/) is the plain rule.

## Theming

Every styled property reads a **component-scoped `--fluid-fold-*` token that
falls back to a main semantic var** (the override ladder). The **complete
list** is in the [API table below](#api).

```css title="brand.css"
[data-fluid-brand="custom"] {
  --fluid-fold-line-color: var(--fluid-border-default);
  --fluid-fold-fg: var(--fluid-text-secondary);
}
```

### Beyond tokens

The toggle (lines included) is `::part(toggle)`, the unfolded region is
`::part(body)`:

```css
fluid-fold::part(toggle) {
  text-transform: uppercase;
  letter-spacing: 0.08em;
}
```

## Accessibility

- Follows the WAI-ARIA **disclosure** pattern: a native `<button>` carrying
  `aria-expanded` and `aria-controls`, in front of a `role="region"` labelled
  by that button.
- The whole line is the button, not only the words, so the target is as wide
  as the page.
- Folded content carries `hidden`, so it is out of the accessibility tree and
  cannot be tabbed into while folded.
- The reveal animation honors `prefers-reduced-motion`.

### AA vs AAA

The fold ships **WCAG 2.2 Level AA** by default and scales to **AAA** on a
switch: it reads the conformance tokens rather than hard-coding sizes, so an
ancestor setting `data-fluid-conformance="aaa"` grows the toggle's hit target
to 44px and the focus ring to 3px with zero per-component branching.

| Token | AA | AAA | Criterion |
| --- | --- | --- | --- |
| `--fluid-target-min` | 24px | **44px** | 2.5.8 → [2.5.5 Target Size (Enhanced)](https://www.w3.org/WAI/WCAG22/Understanding/target-size-enhanced) |
| `--fluid-focus-ring-width` | 2px | **3px** | 2.4.7 → [2.4.13 Focus Appearance](https://www.w3.org/WAI/WCAG22/Understanding/focus-appearance) |
