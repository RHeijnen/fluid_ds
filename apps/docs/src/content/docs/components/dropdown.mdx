`<fluid-dropdown>` is the menu pattern, a trigger that opens a list of actions.
Items are `<fluid-dropdown-item>` elements in three kinds: `item` (default,
fires an event), `checkbox` (toggles), or `separator` (a visual rule). The menu
panel shares its surface with [`<fluid-select>`](/components/select/) and
[`<fluid-typeahead>`](/components/typeahead/), so every popover menu reads as one
family.

Every menu on this page is live. Open one and try the arrow keys, <kbd>Home</kbd>
/ <kbd>End</kbd>, typing a letter to jump, and <kbd>Escape</kbd> to close.

<Demo>

    <fluid-button slot="trigger" variant="secondary" caret>
      Actions
    </fluid-button>
    <fluid-dropdown-item value="edit">Edit</fluid-dropdown-item>
    <fluid-dropdown-item value="duplicate">Duplicate</fluid-dropdown-item>
    <fluid-dropdown-item type="separator"></fluid-dropdown-item>
    <fluid-dropdown-item value="delete">Delete</fluid-dropdown-item>
  </fluid-dropdown>
</Demo>

## Install

The dropdown registers `<fluid-dropdown>` and `<fluid-dropdown-item>` together.
The trigger is any element you slot in; it's almost always a
`<fluid-button>`, so load that too.

<Tabs syncKey="install">
  <TabItem label="CDN">

    <link rel="stylesheet" href="https://cdn.jsdelivr.net/npm/@fluid-ds/tokens@latest/dist/base.css" />

## Examples

### Basic menu

Give the trigger a [`caret`](/components/button/#dropdown-trigger) so it
renders the built-in chevron and rotates while the menu is open. A
`type="separator"` item draws a rule and is skipped by both the pointer and the
keyboard.

### Icons and shortcut hints

Each item has a `prefix` and a `suffix` slot. Put a
[`<fluid-icon>`](/components/icon/) in the prefix and a shortcut hint in the
suffix; the label takes the space between them, so every suffix lands flush on
the right edge of the menu.

<Demo>
  <fluid-dropdown>
    <fluid-button slot="trigger" variant="secondary" caret>
      File
    </fluid-button>
    <fluid-dropdown-item value="new">
      <fluid-icon slot="prefix" name="plus"></fluid-icon>
      New
      <span slot="suffix">⌘N</span>
    </fluid-dropdown-item>
    <fluid-dropdown-item value="duplicate">
      <fluid-icon slot="prefix" name="copy"></fluid-icon>
      Duplicate
      <span slot="suffix">⌘D</span>
    </fluid-dropdown-item>
    <fluid-dropdown-item value="save">
      <fluid-icon slot="prefix" name="save"></fluid-icon>
      Save
      <span slot="suffix">⌘S</span>
    </fluid-dropdown-item>
  </fluid-dropdown>
</Demo>

<ConformanceCode
  code={`<fluid-dropdown>

Give every item in one menu an icon, or none of them: the prefix slot is not a
fixed-width column, so a half-iconed menu leaves its labels out of line.

<Aside type="note">
  The shortcut hint is decorative text, not a live binding. Register the real
  key handler yourself (or with [`<fluid-hotkey>`](/components/hotkey/)) so the
  hint and the behavior can't drift apart.
</Aside>

### Checkbox items

`type="checkbox"` items toggle **without closing the menu**, so a reader can
flip several in a row. Open the menu below and click a couple: the check marks
persist, and the menu only closes on a click outside, on <kbd>Tab</kbd>, or on
the <kbd>Escape</kbd> key. A checkbox item's check mark occupies the prefix
position, so it can't also carry a prefix icon.

<Demo>
  <fluid-dropdown>
    <fluid-button slot="trigger" variant="secondary" caret>
      View options
    </fluid-button>
    <fluid-dropdown-item type="checkbox" value="grid" checked>
      Show grid
    </fluid-dropdown-item>
    <fluid-dropdown-item type="checkbox" value="ruler">
      Show rulers
    </fluid-dropdown-item>
    <fluid-dropdown-item type="checkbox" value="snap" checked>
      Snap to grid
    </fluid-dropdown-item>
  </fluid-dropdown>
</Demo>

<ConformanceCode
  code={`<fluid-dropdown>
  <fluid-button slot="trigger" variant="secondary" caret>View options</fluid-button>

A checkbox item still fires `fluid-select` on every toggle, with the item's new
`checked` value already applied. Read it off `event.detail.item.checked`.

### Disabled items and a disabled menu

`disabled` on an item greys it out and takes it out of the arrow-key and
type-ahead order, so it can never be activated. `disabled` on the dropdown
itself stops the trigger opening anything at all. Both are live below: the first
menu opens with one dead entry, the second doesn't open.

### Placement

The menu is positioned by Fluid's own engine and rendered in the top layer, so
it is never clipped by an ancestor's `overflow` or `transform`. Set `placement`
to pick the preferred side; it auto-flips when there isn't room. `distance`
(in px) tunes the gap between trigger and menu. Open each of these to see where
they land:

    <fluid-dropdown-item value="b">Second</fluid-dropdown-item>

Standard placements are `top` `right` `bottom` `left`, each optionally suffixed
with `-start` or `-end`. The default is `bottom-start`.

### Opening it yourself

`open` reflects the menu state and is writable, so you can open a menu from
somewhere else on the page (a toolbar shortcut, a "what can I do here?" hint).
The trigger still has to be present, that's what the menu anchors to. Both
buttons below drive the same live menu:

<Demo>
  <fluid-dropdown id="dropdown-controlled" placement="bottom-start">
    <fluid-button slot="trigger" variant="secondary" caret>
      Anchored trigger
    </fluid-button>
    <fluid-dropdown-item value="rename">Rename</fluid-dropdown-item>
    <fluid-dropdown-item value="archive">Archive</fluid-dropdown-item>
  </fluid-dropdown>
  <fluid-button onclick="document.getElementById('dropdown-controlled').open = true;">
    Open it
  </fluid-button>
  <fluid-button
    variant="ghost"
    onclick="document.getElementById('dropdown-controlled').open = false;"
  >
    Close it
  </fluid-button>
</Demo>

```ts
const menu = document.querySelector("fluid-dropdown");
menu.open = true; // open from anywhere
menu.open = false; // and close it again
```

## Listening for changes

`<fluid-dropdown>` fires **`fluid-select`** with `{ value, item }` in `detail`
when an item is chosen, by pointer or by keyboard. The event bubbles from the
dropdown, so one listener on a toolbar covers every menu inside it. The
dropdown also fires `fluid-show` and `fluid-hide` when the panel opens and
closes.

<Tabs syncKey="framework">
  <TabItem label="HTML">
    ```html
    <fluid-dropdown id="menu">…</fluid-dropdown>

    <script type="module">
      document.getElementById("menu").addEventListener("fluid-select", (e) => {
        console.log("chose:", e.detail.value);
      });
    </script>
    ```

  </TabItem>
  <TabItem label="React">
    ```tsx title="Menu.tsx"
    import { useRef, useEffect } from "react";
    import "@fluid-ds/components/define/dropdown";

    export function Menu() {
      const ref = useRef<HTMLElement>(null);
      useEffect(() => {
        const el = ref.current!;
        const onSelect = (e: Event) =>
          console.log((e as CustomEvent).detail.value);
        el.addEventListener("fluid-select", onSelect);
        return () => el.removeEventListener("fluid-select", onSelect);
      }, []);
      return (
        <fluid-dropdown ref={ref}>
          <button slot="trigger">Actions</button>
          <fluid-dropdown-item value="edit">Edit</fluid-dropdown-item>
        </fluid-dropdown>
      );
    }
    ```

  </TabItem>
  <TabItem label="Vue">
    ```vue title="Menu.vue"
    <script setup lang="ts">
    import "@fluid-ds/components/define/dropdown";
    const onSelect = (e: CustomEvent) => console.log(e.detail.value);
    </script>

    <template>
      <fluid-dropdown @fluid-select="onSelect">
        <button slot="trigger">Actions</button>
        <fluid-dropdown-item value="edit">Edit</fluid-dropdown-item>
      </fluid-dropdown>
    </template>
    ```

  </TabItem>
  <TabItem label="Angular">

    @Component({

        console.log(e.detail.value);
      }
    }

### Reading a checkbox item

`detail.item` is the element itself, so a checkbox item tells you its new state
directly. Branch on `detail.item.type` when one menu mixes both kinds:

```js
menu.addEventListener("fluid-select", (e) => {
  const { value, item } = e.detail;
  if (item.type === "checkbox") console.log(value, "->", item.checked);
  else console.log("ran action", value);
});
```

## Theming

Every styled property reads a **component-scoped token that falls back to a main
semantic var** (the override ladder): the menu exposes `--fluid-dropdown-*` and
each item exposes `--fluid-dropdown-item-*`. The menu shares the
select / typeahead listbox surface, so overriding the panel here keeps all three
in step. The **complete list** is in the [API tables below](#api).

```css title="brand.css"
/* Every menu under a brand wrapper. */
[data-fluid-brand="custom"] {
  --fluid-dropdown-bg: var(--fluid-surface-base);
  --fluid-dropdown-border: var(--fluid-border-default);
  --fluid-dropdown-item-active-accent: var(--fluid-accent-base);
}

/* One menu with squared-off corners. */
[data-fluid-id="row-actions"] {
  --fluid-dropdown-radius: 4px;
}
```

<Aside type="tip">
  The [Theme builder](/playground/) lets you select a dropdown and tweak the panel and item tokens
  visually, then exports the CSS.
</Aside>

### Beyond tokens: `::part()`

The container exposes [`part="base"`](#api) and `part="menu"`. Reach them with
[`::part()`](https://developer.mozilla.org/en-US/docs/Web/CSS/::part) for CSS
not covered by a token:

```css
/* A wider panel for long labels, no new token needed. */
fluid-dropdown.wide::part(menu) {
  min-width: 18rem;
}
```

## When to use

- A button that reveals a small list of **actions**.
- Quick settings and view toggles (the checkbox items above).
- The overflow menu on a card header or a table row.

### When _not_ to use

- **Picking a value** for a form: use [`<fluid-select>`](/components/select/),
  which is form-associated and submits with the form.
- **Arbitrary panel content** (fields, prose, a mini form): use
  [`<fluid-popover>`](/components/popover/); a menu should only hold items.
- **A right-click menu**: use
  [`<fluid-context-menu>`](/components/context-menu/).
- **A long, searchable list**: use
  [`<fluid-typeahead>`](/components/typeahead/) or
  [`<fluid-command-palette>`](/components/command-palette/).

## Accessibility

Implements the WAI-ARIA Menu pattern. The cross-component contract is in the
[Accessibility guide](/guides/accessibility/).

### Keyboard

| Key                                                | Action                                              |
| -------------------------------------------------- | --------------------------------------------------- |
| <kbd>↑</kbd> / <kbd>↓</kbd>                        | Move the active item.                               |
| <kbd>Home</kbd> / <kbd>End</kbd>                   | Jump to the first / last item.                      |
| _type a letter_                                    | Jump to the next item starting with it.             |
| <kbd>Enter</kbd> / <kbd>Space</kbd>                | Activate the item.                                  |
| <kbd>Escape</kbd>                                  | Close the menu (focus returns to the trigger).      |
| <kbd>Tab</kbd> / <kbd>Shift</kbd> + <kbd>Tab</kbd> | Close and move forward / backward from the trigger. |

Opening the menu keeps DOM focus on the menu panel and marks the first enabled
item active. Escape and item activation restore focus to the trigger. Tab and
outside-pointer dismissal allow focus to move to the next intended control.

### Names & roles

- The inner panel is `role="menu"`; items are `role="menuitem"` (or
  `menuitemcheckbox`); the trigger gets `aria-haspopup="menu"` +
  `aria-expanded`. The menu renders in the **top layer**, so it's never clipped.
- Checkbox items expose `aria-checked`; ordinary items and separators do not.
  Disabled items cannot activate, and separators are not selectable.
- An icon-only trigger has no text to name it, so give it an `aria-label`
  ("Row actions", "Report actions"), the same rule as an
  [icon-only button](/components/button/#names).
- The panel uses `ariaActiveDescendantElement` to reference the active slotted
  item across the shadow boundary. This targets current browsers with ARIA
  element reflection; older engines without that API are outside this contract.
  The optional trigger `aria-controls` string is omitted because its ID cannot
  resolve a panel in another tree. Browser automation does not replace manual
  assistive-technology testing.

### Motion & target size

- The open/close pop honors `prefers-reduced-motion`.
- Interactive items floor their height to `--fluid-target-min` (≥ **24px** AA /
  **44px** AAA); separators are exempt.

### AA vs AAA

Targets **WCAG 2.2 AA**; manual assistive-technology review remains required.
The **Conformance** toggle at the top of this page (or an ancestor
`[data-fluid-conformance="aaa"]`) lifts:

| Token                      | AA   | AAA      | Criterion                                                                                                |
| -------------------------- | ---- | -------- | -------------------------------------------------------------------------------------------------------- |
| `--fluid-target-min`       | 24px | **44px** | 2.5.8 → [2.5.5 Target Size (Enhanced)](https://www.w3.org/WAI/WCAG22/Understanding/target-size-enhanced) |
| `--fluid-focus-ring-width` | 2px  | **3px**  | 2.4.7 → [2.4.13 Focus Appearance](https://www.w3.org/WAI/WCAG22/Understanding/focus-appearance)          |
