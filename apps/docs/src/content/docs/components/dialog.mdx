`<fluid-dialog>` wraps the native `<dialog>` element, so the browser handles the
focus trap, backdrop, and top-layer rendering for free. You get a styled,
themable shell on top: label / body / footer slots, an optional built-in close
button, and a backdrop click that dismisses by default.

Every dialog on this page is real. Open one and try <kbd>Tab</kbd> (focus stays
inside), <kbd>Escape</kbd>, and a click on the backdrop.

<Demo>
  <fluid-button onclick="document.querySelector('#hero-dialog').show()">Open dialog</fluid-button>
  <fluid-dialog id="hero-dialog">
    <span slot="label">Confirm delete</span>
    <p>This permanently deletes the item, there's no undo.</p>
    <div slot="footer">
      <fluid-button variant="ghost" onclick="document.querySelector('#hero-dialog').hide()">
        Cancel
      </fluid-button>
      <fluid-button tone="danger" onclick="document.querySelector('#hero-dialog').hide()">
        Delete
      </fluid-button>
    </div>
  </fluid-dialog>
</Demo>

### Dismiss behavior

A click on the backdrop closes the dialog by default. Add `no-light-dismiss`
when a stray click would lose work, and `no-close-button` to drop the built-in
× so the footer buttons are the only way out. Open both and try clicking
outside the panel: the first closes, the second doesn't.

<Demo>
  <fluid-button variant="secondary" onclick="document.querySelector('#dialog-light').show()">
    Backdrop closes it
  </fluid-button>
  <fluid-button variant="secondary" onclick="document.querySelector('#dialog-sticky').show()">
    Backdrop does nothing
  </fluid-button>
  <fluid-dialog id="dialog-light">

    <p>Click the backdrop, press Escape, or use the × in the corner.</p>
  </fluid-dialog>

<Aside type="caution">
  <kbd>Escape</kbd> is handled by the native `<dialog>` element and can't be
  switched off. Never design a flow that depends on the user being unable to
  leave: keep the destructive path behind an explicit button, and make closing
  the safe outcome.
</Aside>

### A form inside a dialog

The common real-world dialog is a small form. Wrap the **whole dialog** in the
`<form>`, not just the body: a `type="submit"` button finds its form with
`closest("form")`, so a footer button only submits when the form is an ancestor
of the dialog. Submit the live one below and it writes the value back to the
page, then closes itself.

### Programmatic control

`show()` and `hide()` are the whole imperative surface, and `open` reflects the
state as an attribute so CSS and tests can see it. Setting `open` directly does
the same thing as calling the methods. The button below opens a dialog and
closes it again two seconds later, without a click:

<Demo>
  <fluid-button
    variant="secondary"
    onclick="const d = document.querySelector('#dialog-timed'); d.show(); setTimeout(() => d.hide(), 2000);"
  >
    Open for two seconds
  </fluid-button>
  <fluid-dialog id="dialog-timed" size="sm">
    <span slot="label">Closing shortly</span>
    <p>This dialog closes itself in two seconds. Escape still beats the timer.</p>
  </fluid-dialog>
</Demo>

```ts
const dialog = document.querySelector("fluid-dialog");
dialog.show(); // same as dialog.open = true
dialog.hide(); // same as dialog.open = false

dialog.addEventListener("fluid-hide", () => {
  console.log("user dismissed");
});
```

<Aside type="note">
  `hide()` returns immediately: the close animation is still running when the call resolves. If you
  need to act once the dialog is really gone (restoring focus somewhere unusual, tearing down
  state), do it in the `fluid-hide` handler below rather than on the line after `hide()`.
</Aside>

## Listening for changes

`<fluid-dialog>` fires **`fluid-show`** when it opens and **`fluid-hide`** when
it closes (button, <kbd>Escape</kbd>, or backdrop). Drive it with `show()` /
`hide()`.

<Tabs syncKey="framework">
  <TabItem label="HTML">
    ```html
    <fluid-dialog id="d">…</fluid-dialog>

    <script type="module">
      const d = document.getElementById("d");
      d.addEventListener("fluid-hide", () => console.log("closed"));
      d.show();
    </script>
    ```

  </TabItem>
  <TabItem label="React">
    ```tsx title="Confirm.tsx"
    import { useRef, useEffect } from "react";
    import "@fluid-ds/components/define/dialog";

    export function Confirm() {
      const ref = useRef<HTMLElement & { show(): void }>(null);
      useEffect(() => {
        const el = ref.current!;
        const onHide = () => console.log("closed");
        el.addEventListener("fluid-hide", onHide);
        return () => el.removeEventListener("fluid-hide", onHide);
      }, []);
      return <fluid-dialog ref={ref}><span slot="label">Hi</span>…</fluid-dialog>;
    }
    ```

  </TabItem>
  <TabItem label="Vue">
    ```vue title="Confirm.vue"

    import "@fluid-ds/components/define/dialog";
    </script>

    <template>
      <fluid-dialog @fluid-hide="() => {}"><span slot="label">Hi</span>…</fluid-dialog>
    </template>
    ```

  </TabItem>
  <TabItem label="Angular">

    ```ts title="confirm.component.ts"
    import "@fluid-ds/components/define/dialog";

    @Component({
      standalone: true,
      schemas: [CUSTOM_ELEMENTS_SCHEMA],
      selector: "app-confirm",
      template: `<fluid-dialog (fluid-hide)="onHide()"><span slot="label">Hi</span>…</fluid-dialog>`
    })
    export class Confirm {
      onHide() {}
    }
    ```

## Theming

Every styled property reads a **component-scoped `--fluid-dialog-*` token that
falls back to a main semantic var** (the override ladder), including the
backdrop (`--fluid-dialog-backdrop`), radius, and separators. The **complete
list** is in the [API table below](#api).

```css title="brand.css"
/* Every dialog under a brand wrapper. */
[data-fluid-brand="custom"] {
  --fluid-dialog-bg: var(--fluid-surface-base);
  --fluid-dialog-radius: 12px;
  --fluid-dialog-backdrop: rgb(0 0 0 / 0.5);
}

/* One dialog with a heavier scrim, for a destructive confirmation. */
[data-fluid-id="destructive-confirm"] {
  --fluid-dialog-backdrop: rgb(0 0 0 / 0.75);
}
```

<Aside type="tip">
  The [Theme builder](/playground/) lets you select a dialog and tweak the panel, backdrop, and
  radius tokens visually, then exports the CSS.
</Aside>

### Beyond tokens: `::part()`

The native element is [`part="base"`](#api); inside are `part="panel"`,
`part="header"`, `part="body"`, `part="footer"`, and `part="close"`. Reach them
with [`::part()`](https://developer.mozilla.org/en-US/docs/Web/CSS/::part) for
CSS not covered by a token:

```css
/* A taller scroll area for a dialog that is mostly a list. */
fluid-dialog.picker::part(body) {
  max-height: 60vh;
}
```

## When to use

- A blocking interaction the user must respond to before continuing
  (confirm delete, sign in, complete a short form).
- Anything that fits on one screen and needs the user's full attention.

### When _not_ to use

- **A side-anchored panel** (settings, filters, nav): use
  [`<fluid-drawer>`](/components/drawer/).
- **Contextual content that shouldn't block**: use
  [`<fluid-popover>`](/components/popover/), or
  [`<fluid-dropdown>`](/components/dropdown/) for a list of actions.
- **A confirmation that just needs a nudge**: a full modal for "delete this
  tag?" is heavy. Use [`<fluid-popconfirm>`](/components/popconfirm/) anchored
  to the button.
- **Telling the user something succeeded**: nothing to answer, so don't block.
  Use [`<fluid-toast>`](/components/toast/).

## Accessibility

The dialog is built on the native `<dialog>` element, so it inherits the
platform's modal semantics. The cross-component contract is in the
[Accessibility guide](/guides/accessibility/).

### Focus & keyboard

- `showModal()` provides the **focus trap**: focus moves into the dialog on
  `show()` and is **restored** to the previously focused element on `hide()`
  ([SC 2.4.3](https://www.w3.org/WAI/WCAG22/Understanding/focus-order)).
- <kbd>Escape</kbd> closes the dialog (handled natively).
- The dialog renders in the **top layer**, so it's never clipped by ancestor
  `overflow`/`transform`.

### Names & roles

- The native `<dialog>` exposes `role="dialog"` + `aria-modal="true"`.
- The `label` slot is the accessible name; with no label, set `aria-label` on
  the host ([SC 4.1.2](https://www.w3.org/WAI/WCAG22/Understanding/name-role-value)).
  The host moves that value onto the inner native dialog, since `aria-label` is
  not valid on a role-less custom-element host.
- The built-in close button is labeled "Close dialog". If you set
  `no-close-button`, make sure a footer button still offers a way out.

### Motion & target size

- The panel/backdrop entrance animations honor `prefers-reduced-motion`.
- The close button floors its hit area to `--fluid-target-min`: ≥ **24×24**
  (AA) / **44×44** (AAA).

### AA vs AAA

Ships **WCAG 2.2 AA**; the **Conformance** toggle at the top of this page (or an
ancestor `[data-fluid-conformance="aaa"]`) lifts:

| Token                      | AA   | AAA      | Criterion                                                                                                |
| -------------------------- | ---- | -------- | -------------------------------------------------------------------------------------------------------- |
| `--fluid-target-min`       | 24px | **44px** | 2.5.8 → [2.5.5 Target Size (Enhanced)](https://www.w3.org/WAI/WCAG22/Understanding/target-size-enhanced) |
| `--fluid-focus-ring-width` | 2px  | **3px**  | 2.4.7 → [2.4.13 Focus Appearance](https://www.w3.org/WAI/WCAG22/Understanding/focus-appearance)          |
