`<fluid-countdown>` ticks down to a `target` ISO datetime or across a fixed
`seconds` duration. It renders either labelled day / hour / minute / second
**segments** or a compact **clock** (`HH:MM:SS`), updating once a second. The
readout sits in a `role="timer"` region with a throttled `aria-live="polite"`
announcement, and it emits **`fluid-tick`** every second plus **`fluid-complete`**
at zero.

<Demo>
  <fluid-countdown seconds="90061" format="segments"></fluid-countdown>
</Demo>

### Counting to a target

Pass an ISO datetime string as `target` and the countdown ticks toward it,
re-reading the wall clock each second so it stays accurate even if the tab is
throttled.

```html
<fluid-countdown target="2026-12-31T23:59:59Z" format="segments"></fluid-countdown>
```

### Controlling it

`autostart` is on by default. Set it off to start the countdown yourself, and
use the `start()`, `pause()`, and `reset()` methods.

```html
<script type="module">
  import "@fluid-ds/components/define/countdown";
  const c = document.createElement("fluid-countdown");
  c.autostart = false;
  c.seconds = 120;
  document.body.append(c);
  c.start();
  // c.pause();
  // c.reset();
</script>
```

`autostart` is a Boolean property. The string attribute `autostart="false"`
does not disable it; assign the property before connecting the element.

### Localization

Import the desired [locale pack](/guides/localization/) and declare `lang` on
the countdown or an ancestor, including a containing shadow host. The timer
name, short unit labels, complete remaining-time sentence and completion
message use the translation registry. Spoken durations use `Intl.NumberFormat`
unit grammar and `Intl.ListFormat`; visible clock/segment digits remain ASCII
for compatibility. Message formatting follows the registry's effective language:
declared context, then document/browser language, then English. Malformed Intl
language tags use English unit formatting; an empty nearest language follows
the registry's document/browser fallback. This differs from the standalone
formatters' explicit-locale/inherited-language/English policy.

Changing language updates the last announced duration or completion message,
including while paused, without advancing the countdown or emitting another
completion event. The ten-second announcement throttle and `reset()` behavior
are unchanged. An explicit `aria-label`, including an empty string, remains
application-owned; provide a meaningful name for accessible use.

Custom dictionaries can override `countdownRemaining(duration)` and
`countdownComplete`. The duration argument is an already-localized display
string, not raw seconds; the callback owns the complete sentence. The official
Dutch, German, French, Spanish and Arabic message drafts still require fluent
review. Browser context tests do not establish native-ancestor SSR inheritance
or screen-reader announcement quality.

### Disconnect and reconnect

`start()` retains its immediate first tick. An immediate completion does not
install another interval, and the first render reflects that tick's value.
Disconnect removes the interval without emitting detached ticks. Reconnecting
an active fixed-duration countdown resumes the remaining duration with one
immediate tick; time spent detached does not consume that duration. A valid
`target` instead uses elapsed wall-clock time on reconnect. A manually paused
countdown remains paused, including when `autostart` was initially enabled.

## Events

`<fluid-countdown>` fires **`fluid-tick`** on every one-second tick (with
`detail.remaining`, the whole seconds left) and **`fluid-complete`** once when
the remaining time reaches zero.

## When to use

- A sale or offer that expires at a fixed time.
- A "resend code" / rate-limit cooldown before an action becomes available.
- A live-event lobby ticking down to kickoff.

For an open-ended elapsed timer (counting up) or a progress indicator, reach for
a different component: `<fluid-countdown>` only counts down.

## Theming

Every styled property reads a **component-scoped `--fluid-countdown-*` token
that falls back to a main semantic var** (the override ladder). The **complete
list** is in the [API table below](#api).

```css title="brand.css"
[data-fluid-brand="custom"] {
  --fluid-countdown-digit-fg: var(--fluid-text-primary);
  --fluid-countdown-separator-fg: var(--fluid-text-secondary);
  --fluid-countdown-label-fg: var(--fluid-text-secondary);
}
```

### Beyond tokens: `::part()`

The region is [`part="base"`](#api), with `part="segment"`, `part="digit"`,
`part="label"`, and `part="separator"` for the pieces. Reach them with
[`::part()`](https://developer.mozilla.org/en-US/docs/Web/CSS/::part) for CSS not
covered by a token.

## Accessibility

- The readout lives in a `role="timer"` region with an accessible name (default
  "Time remaining", override via `aria-label` on the host).
- A visually hidden `aria-live="polite"` companion carries the spoken update.
  Announcements are **throttled** to about once every 10 seconds, plus a final
  one at zero, so a screen reader is not flooded with one update per tick. The
  visible digits still update every second.
- The clock separators (`:`) are `aria-hidden`, so the live text reads as a
  localized sentence rather than punctuation.
- Honor `prefers-reduced-motion`: the component has no animation, so there's
  nothing to suppress.
