The table expansion pack provides two deliberately separate components.
`<fluid-table>` renders a compact semantic
`<table>` with a `<caption>`, `<th scope="col">` headers, and a data-driven
body. It is sortable (string + numeric aware), optionally selectable with
checkboxes, fully themable through `--fluid-table-*` tokens, and works in any
framework. `<fluid-infinite-table>` handles large asynchronously loaded
datasets with rich cell templates, sticky projected filters and headers,
windowed rows, column configuration, and an infinite-load event.

The table below is live over 500 generated deployment records: scroll it and
only a small window of rows ever exists in the DOM (the readout underneath
counts them), click a header to sort, open the Columns dialog, and keep
scrolling to trigger the infinite-load sentinel.

See it running: the [data table demo](/demos/data-table/) puts
`<fluid-infinite-table>` on a large dataset with windowed rows, infinite
loading, sorting, filters, a column manager and a persisted layout.

## Install

```bash
pnpm add @fluid-ds/table
```

Import only the piece you use:

```ts
import "@fluid-ds/table/define/table";
import "@fluid-ds/table/define/infinite-table";
```

## Components

| Tag                      | Use                                                                                                                       |
| ------------------------ | ------------------------------------------------------------------------------------------------------------------------- |
| `<fluid-table>`          | Accessible data table: column-driven, sortable headers, optional row selection, themable.                                 |
| `<fluid-infinite-table>` | Template-driven operational table: infinite loading, row windowing, sticky filters and headers, and configurable columns. |

## Use

Pass `columns` and `rows` as properties (use property binding in your
framework, or set them in script). Each row is a plain object keyed by
`column.key`; an `id` field, when present, becomes the stable row key.
Use unique IDs when filtering or replacing records: without an ID, selection
uses the record's index in the supplied `rows` array. Sorting retains that
original index, including when the same object appears more than once.
Empty and nullish sort values remain last in both directions. Filtering and
paging are application-owned; replace `rows` with the desired result set.

```html
<fluid-table id="people" caption="Contributors" selectable></fluid-table>

<script type="module">
  import "@fluid-ds/table/define/table";

  const el = document.getElementById("people");
  el.columns = [
    { key: "name", label: "Name", sortable: true },
    { key: "role", label: "Role", sortable: true },
    { key: "commits", label: "Commits", sortable: true, align: "end" }
  ];
  el.rows = [
    { id: 1, name: "Ada Lovelace", role: "Engineer", commits: 312 },
    { id: 2, name: "Grace Hopper", role: "Architect", commits: 1290 }
  ];
  el.sort = { key: "commits", dir: "desc" };

  el.addEventListener("fluid-sort", (e) => console.log(e.detail)); // { key, dir }
  el.addEventListener("fluid-selection-change", (e) => console.log(e.detail)); // { selected: [...] }
</script>
```

## Infinite and template-driven data

Use `<fluid-infinite-table>` when the server owns paging and sorting, or when
cells need to render complete components instead of string values. A cell
renderer receives `{ row, rowIndex, column, value }`. It can return a Lit
template, custom element, native element, or plain value.

```ts
import { html } from "lit";
import "@fluid-ds/table/define/infinite-table";

const table = document.querySelector("fluid-infinite-table");

table.columns = [
  {
    key: "terminal",
    label: "Terminal",
    width: "16rem",
    sortable: true,
    renderCell: ({ row }) => html`
      <a href="/terminals/${row.id}">
        <strong>${row.name}</strong>
        <small>${row.serialNumber}</small>
      </a>
    `
  },
  {
    key: "status",
    label: "Status",
    width: "9rem",
    renderCell: ({ row }) => html`
      <fluid-badge tone=${row.online ? "success" : "danger"}>
        ${row.online ? "Online" : "Offline"}
      </fluid-badge>
    `
  },
  { key: "site", path: "site.name", label: "Site", width: "12rem" }
];

table.rows = firstPage.documents;
table.total = firstPage.count;
table.hasMore = table.rows.length < table.total;

table.addEventListener("fluid-load-more", async (event) => {
  if (table.loading) return;
  table.loading = true;
  table.error = "";
  try {
    const nextPage = await loadTerminals(event.detail.offset);
    table.rows = [...table.rows, ...nextPage.documents];
    table.total = nextPage.count;
    table.hasMore = table.rows.length < table.total;
  } catch {
    table.error = "Could not load more terminals. Try again.";
    table.hasMore = false; // Re-enable deliberately when the user retries.
  } finally {
    table.loading = false;
  }
});

table.addEventListener("fluid-column-layout-change", (event) => {
  savePreference("terminal-table", event.detail.layout);
});
```

Project application-owned filters into the sticky toolbar:

```html
<fluid-infinite-table
  caption="Terminal fleet"
  hide-caption
  configurable
  scroll-mode="container"
  style="--fluid-infinite-table-height: 42rem"
>
  <payter-filter-bar slot="filters"></payter-filter-bar>
</fluid-infinite-table>
```

Fluid emits serializable layout data but does not choose a persistence
mechanism. Applications can store it in a user profile, local storage, a
database, or another preference service.

Windowing assumes a fixed row height. Set `row-height` to match your rendered
rows; zero, negative, or non-finite values fall back to 64px. Overscan is a
non-negative integer. Replacing a deeply scrolled dataset with fewer results
clamps the rendered window to available rows, and removing/reinserting the
element reattaches its scroll and intersection observers.

### Column reorder and resize

With `reorderable-columns`, a header is dragged by any point of itself and
the columns rearrange live under the pointer as a preview of the drop;
Escape puts the original order back. Each header also carries a keyboard
grab handle: Enter or Space picks the column up, arrow keys move it, Enter
drops it. With `resizable-columns`, each header carries a grip on its
trailing edge: drag it, double-click (or press Enter) to auto-fit the column
to its contents, arrow keys to size it a step at a time (Shift for a bigger
step), Home to restore the declared width.

Order and width are the same kind of fact as visibility, so all three travel
in one `layout` and leave in one `fluid-column-layout-change`. A consumer
that already persists a layout persists a resize and a reorder for free. Set
`resizable: false` on an individual column definition to pin its width.

The handle names and the move announcement are localizable through the
`resize-column-label`, `reorder-column-label`, and `column-position-label`
properties; `{column}`, `{position}`, and `{count}` are substituted.

### Column scrolling (`column-scroll`)

By default the table trusts its container to scroll or grow when the columns
are wider than the viewport. Set `column-scroll` and the table owns the
problem instead: columns wider than the container scroll behind a horizontal
scrollbar of the table's own. The scrollbar lives between the header and the
rows (a bar at the bottom of a windowed list is wherever the list currently
ends, which is nowhere to look for it), and it moves the header and the rows
together, so columns never shear against their own headers. It only appears
while there is somewhere to scroll to.

```html
<fluid-infinite-table column-scroll></fluid-infinite-table>
```

### Toolbar slots and the column manager

The sticky toolbar accepts host content in two slots: `toolbar-actions`
places controls at the end of the toolbar, after the row count and the
built-in Columns button, and `toolbar-secondary` renders a full-width second
toolbar line (removed from layout when empty). To replace the built-in
Columns button with your own control, set `configurable` to `false` and call
the public `openColumnManager()` method: the dialog is rendered regardless
of `configurable`, only the button is gated.

```html
<fluid-infinite-table id="fleet" caption="Terminal fleet">
  <fluid-button slot="toolbar-actions" id="cols">Columns</fluid-button>
  <div slot="toolbar-secondary">Bulk actions…</div>
</fluid-infinite-table>

<script>
  document.getElementById("cols").addEventListener("click", () => {
    document.getElementById("fleet").openColumnManager();
  });
</script>
```

### Infinite table properties

| Property                | Type                             | Default                                    | Notes                                                                          |
| ----------------------- | -------------------------------- | ------------------------------------------ | ------------------------------------------------------------------------------ |
| `columns`               | `FluidInfiniteTableColumn[]`     | `[]`                                       | Supports nested `path`, width, visibility, sorting, and header/cell renderers. |
| `rows`                  | `Record<string, unknown>[]`      | `[]`                                       | Currently loaded records.                                                      |
| `total`                 | `number`                         | `0`                                        | Total matching records reported by the data source.                            |
| `available-total`       | `number`                         | `0`                                        | Optional unfiltered total shown after the matching count.                      |
| `loading`               | `boolean`                        | `false`                                    | Announces the loading state.                                                   |
| `has-more`              | `boolean`                        | `false`                                    | Enables the infinite-load sentinel.                                            |
| `virtual`               | `boolean`                        | `true`                                     | Windows loaded rows to bound DOM size.                                         |
| `row-height`            | `number`                         | `64`                                       | Fixed row height used by the windowing calculation.                            |
| `overscan`              | `number`                         | `6`                                        | Extra rows rendered above and below the viewport.                              |
| `scroll-mode`           | `"document" \| "container"`      | `"document"`                               | Uses page scrolling or a constrained component viewport.                       |
| `configurable`          | `boolean`                        | `false`                                    | Exposes the column visibility and ordering dialog.                             |
| `clickable`             | `boolean`                        | `false`                                    | Makes rows keyboard-focusable and emits row activation from Enter or Space.    |
| `layout`                | `FluidInfiniteTableLayoutItem[]` | `[]`                                       | Restores a previously saved layout.                                            |
| `reorderable-columns`   | `boolean`                        | `false`                                    | Columns can be dragged, or moved from the keyboard, into another order.        |
| `resizable-columns`     | `boolean`                        | `false`                                    | Column widths can be dragged, auto-fitted, or stepped from the keyboard.       |
| `column-scroll`         | `boolean`                        | `false`                                    | Opt-in horizontal column scrollbar between header and rows (see above).        |
| `row-key`               | `string`                         | `"id"`                                     | Row field used as the stable row identity.                                     |
| `error`                 | `string`                         | `""`                                       | Error message; when set, the error state (or the `error` slot) is shown.       |
| `resize-column-label`   | `string`                         | `"Resize {column}"`                        | Accessible name for a resize grip.                                             |
| `reorder-column-label`  | `string`                         | `"Reorder {column}"`                       | Accessible name for a reorder handle.                                          |
| `column-position-label` | `string`                         | `"{column}, column {position} of {count}"` | Announcement while a column is moved.                                          |

### Infinite table methods

| Method                | Purpose                                                                                                                                                          |
| --------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `openColumnManager()` | Opens the column configuration dialog. Public so a host that hides the built-in button (`configurable=false`) can reach the dialog from its own toolbar control. |

### Infinite table slots

| Slot                | Content                                                                                              |
| ------------------- | ---------------------------------------------------------------------------------------------------- |
| `filters`           | Application-owned filter controls rendered above the header.                                         |
| `toolbar-actions`   | Host controls placed at the end of the toolbar, after the row count and the built-in Columns button. |
| `toolbar-secondary` | Full-width second toolbar line; removed from layout when empty.                                      |
| `empty`             | Empty-result content.                                                                                |
| `error`             | Error content, shown when `error` is set.                                                            |

### Infinite table events

| Event                        | Detail                             | When                                                                       |
| ---------------------------- | ---------------------------------- | -------------------------------------------------------------------------- |
| `fluid-load-more`            | `{ offset }`                       | The load sentinel approaches the viewport.                                 |
| `fluid-sort`                 | `{ key, dir }`                     | A sortable header is activated.                                            |
| `fluid-column-layout-change` | `{ layout }`                       | Column visibility, order, or width changes; complete and ready to persist. |
| `fluid-row-click`            | `{ row, rowIndex, originalEvent }` | A non-interactive row area is activated.                                   |

## API

### Properties

| Property       | Type                                    | Default | Notes                                                                 |
| -------------- | --------------------------------------- | ------- | --------------------------------------------------------------------- |
| `columns`      | `{ key, label, sortable?, align? }[]`   | `[]`    | Column definitions. `align` is `"start" \| "center" \| "end"`.        |
| `rows`         | `Record<string, unknown>[]`             | `[]`    | Row data keyed by `column.key`.                                       |
| `selectable`   | `boolean`                               | `false` | Adds a leading select-all + per-row checkbox column.                  |
| `sort`         | `{ key, dir: "asc" \| "desc" } \| null` | `null`  | Current sort. Set it to control sorting, or let the headers drive it. |
| `caption`      | `string`                                | `""`    | Table caption text.                                                   |
| `hide-caption` | `boolean`                               | `false` | Keep the caption for screen readers but hide it visually.             |

### Events

| Event                    | Detail                   | When                           |
| ------------------------ | ------------------------ | ------------------------------ |
| `fluid-sort`             | `{ key, dir }`           | A sortable header was toggled. |
| `fluid-selection-change` | `{ selected: string[] }` | The selected row keys changed. |

### Parts

`base`, `caption`, `header-row`, `header-cell`, `sort-button`, `row`, `cell`,
`select-all`, `select-row`.

## Theming

Each styled property reads a component token that falls back to a Fluid
semantic variable, so brand themes flow through automatically and you can
override one table, all tables, or a single instance:

| Token                        | Falls back to                   |
| ---------------------------- | ------------------------------- |
| `--fluid-table-bg`           | `--fluid-surface-base`          |
| `--fluid-table-fg`           | `--fluid-text-primary`          |
| `--fluid-table-header-bg`    | `--fluid-surface-muted`         |
| `--fluid-table-header-fg`    | `--fluid-text-primary`          |
| `--fluid-table-border`       | `--fluid-border-default`        |
| `--fluid-table-row-hover-bg` | `--fluid-surface-muted`         |
| `--fluid-table-selected-bg`  | a tint of `--fluid-accent-base` |
| `--fluid-table-zebra-bg`     | `transparent` (zebra off)       |
| `--fluid-table-radius`       | `--fluid-radius-md`             |
| `--fluid-table-cell-padding` | `0.625rem 0.75rem`              |

Turn on zebra striping by setting `--fluid-table-zebra-bg`.

## Accessibility

- A native `<table>` with `<caption>`, `<thead>`, and `<th scope="col">` gives
  assistive tech full row and column context for free.
- Sortable headers host an `aria-sort` of `ascending`, `descending`, or `none`
  on the `<th>` (not the button), per the WAI-ARIA Table pattern, and the sort
  control is a real `<button>` so it is keyboard operable.
- Selection uses native checkboxes with descriptive `aria-label`s; the
  select-all box reflects an indeterminate state when only some rows are picked.
- The infinite table exposes absolute `aria-rowindex` values for windowed rows.
  Its `aria-rowcount` includes the header, so 100 data records are reported as
  101 table rows. When `has-more` is true and no total is known, the count is
  `-1`. Hidden spacers do not masquerade as data rows.
- This is a static data table, not an interactive grid: Tab moves between the
  header buttons and the checkboxes, and cells are not individually focusable.
  Reach for a Grid when cells must be navigable with arrow keys.
- Focus rings honor `--fluid-focus-ring-width` and interactive targets respect
  `--fluid-target-min`, so the table scales to AAA sizing when an ancestor opts
  in. The sort-icon transition is removed under
  `prefers-reduced-motion: reduce`.

The automated contracts cover representative sorting, stable selection, column
configuration, row activation, data replacement, and next-page requests. They
do not establish complete accessibility conformance. Manual assistive-technology
review and full localization remain open: built-in selection, dialog, and
loading strings are still English, apart from the three configurable column
handle labels listed above.
