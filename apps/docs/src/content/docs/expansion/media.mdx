Media web components for Fluid, themable video, playlists with
auto-advance, GIF/APNG with play/pause control, and pan-and-zoom frames.
Expansion pack.

import { Aside } from "@astrojs/starlight/components";
import MediaDemo from "../../../components/MediaDemo.astro";

Two of the components are live below, with no media files shipped: the audio
player plays a chime synthesized right in your browser, and the zoomable frame
pans and zooms an inline illustration. The video players need real video
sources, so they are shown in code only.

## Install

```bash
pnpm add @fluid-ds/media
```

Import only the pieces you use:

```ts
import "@fluid-ds/media/define/video";
import "@fluid-ds/media/define/video-playlist";
import "@fluid-ds/media/define/animated-image";
import "@fluid-ds/media/define/zoomable-frame";
import "@fluid-ds/media/define/audio";
import "@fluid-ds/media/define/lightbox";
```

## Components

| Tag                      | Use                                                                                                |
| ------------------------ | -------------------------------------------------------------------------------------------------- |
| `<fluid-video>`          | Themed video surface with browser-native playback controls.                                        |
| `<fluid-video-playlist>` | Playlist-driven video player with auto-advance.                                                    |
| `<fluid-animated-image>` | GIF / APNG / animated WebP with play/pause control (canvas-snapshot trick).                        |
| `<fluid-zoomable-frame>` | Pan + zoom container with wheel, drag, and native zoom/pan buttons.                                |
| `<fluid-audio>`          | Themed audio player: custom play/pause, seek slider with time, mute.                               |
| `<fluid-lightbox>`       | Thumbnail gallery that opens images in a modal lightbox (top-layer `<dialog>`, prev/next, Escape). |

## Use

```html
<fluid-video src="/clip.mp4" controls></fluid-video>

<fluid-animated-image src="/cat.gif"></fluid-animated-image>

<fluid-zoomable-frame>
  <img src="/diagram.svg" alt="…" />
</fluid-zoomable-frame>

<fluid-audio src="/track.mp3" label="Episode 12"></fluid-audio>

<fluid-lightbox loop>
  <img src="/a-thumb.jpg" data-full="/a.jpg" alt="Sunrise" />
  <img src="/b-thumb.jpg" data-full="/b.jpg" alt="Harbour" />
</fluid-lightbox>
```

`<fluid-video-playlist>` is driven by its `entries` **property** (a JavaScript
array, not an HTML attribute), so set it from script after the element upgrades:

```html
<fluid-video-playlist auto-advance></fluid-video-playlist>

<script type="module">
  import "@fluid-ds/media/define/video-playlist";

  const playlist = document.querySelector("fluid-video-playlist");
  playlist.entries = [
    { src: "/intro.mp4", title: "Intro" },
    { src: "/chapter-1.mp4", title: "Chapter 1" },
    { src: "/chapter-2.mp4", title: "Chapter 2" }
  ];
</script>
```

`autoAdvance` defaults to `true`: the playlist selects the next entry when the
current clip ends. Set the JavaScript property to `false` to disable it. `loop`
wraps from the last entry to the first. Each track is a native button with
`aria-pressed`, and the current title names the video. `goTo(index)` ignores
out-of-range, fractional, or non-finite indexes. Selection remains usable after
removing and reconnecting the playlist.

### Video sources, captions, and lifecycle

Use `label` to name a player and provide captions for speech. Direct child
`source` and `track` elements are mirrored into the native video, because native
media selection does not traverse shadow slots. The original consumer nodes
remain in the light DOM; changes to their attributes are synchronized.

```html
<fluid-video label="Product introduction" controls>
  <source src="/intro.webm" type="video/webm" />
  <source src="/intro.mp4" type="video/mp4" />
  <track kind="captions" src="/intro.en.vtt" srclang="en" label="English" default />
</fluid-video>
```

`play()` returns the native playback promise, including autoplay or decoder
rejections. Handle that promise in application code. `pause()` and `load()`
delegate to the native player; `nativeElement` exposes its time, error, and text
track APIs. Removing a player pauses playback. Native controls and codec support
remain browser-specific, not a cross-browser custom controls implementation.

The `default` track attribute does not force captions on against native browser
selection preferences. A disabled track may not fetch its cues until selected.
Use the native caption controls, or explicitly select a track through
`nativeElement.textTracks[index].mode = "showing"` when implementing application
controls. Automated checks verify selected, fetched cues during playback; they
do not certify automatic caption selection or caption quality.

### Pan without dragging

The default controls include zoom out, reset, zoom in, and four pan directions.
Tab visits each native button; Enter or Space activates it. Pan buttons move by
`pan-step` CSS pixels (40 by default). `panBy(x, y)` provides the same movement
for application controls. Panning is intentionally unbounded; reset clears both
offsets and restores scale 1, constrained to the configured zoom bounds.

The seven accessible names can be overridden with `zoom-in-label`,
`zoom-out-label`, `reset-label`, `pan-left-label`, `pan-right-label`,
`pan-up-label`, and `pan-down-label`. These are consumer-supplied translations:
the standalone media package does not yet subscribe to core locale bundles.
When using `no-controls`, provide equivalent keyboard and single-pointer
controls in the application; wheel and drag alone are not sufficient.

`<fluid-audio>` wraps a native `<audio>` element for playback but draws its own
accessible controls (the play button is labelled by state, the scrubber is a
slider with `aria-valuetext` time, mute toggles `aria-pressed`). `<fluid-lightbox>`
turns each slotted `<img>` into a focusable button; the lightbox is a native
modal `<dialog>` so it gets focus trapping, Escape-to-close, and the top layer
for free. Set `data-full` on a thumbnail to load a higher-resolution source in
the lightbox.

## Theming

Components read from the same `--fluid-*` semantic tokens as the rest of
the system, focus rings, surface colors, control accents, so themes
flow through without extra work. Each component has its own
`@cssproperty`-annotated tokens for fine-grained overrides; see the
generated tables in each component's reference.

`<fluid-video-playlist>` highlights the active entry with
`--fluid-video-playlist-active-accent`, which falls back to
`--fluid-accent-base`. The generated token table reflects this fallback.

## When to use

- Anywhere you'd reach for native media elements but want consistent
  styling, focus behavior, and pause / play semantics across browsers
  and animation formats.

## Accessibility verification

Automated contracts exercise local video decoding, caption cues, selection,
native keyboard activation, drag cancellation, reconnect, and pan buttons.
They do not replace caption-quality review or screen-reader and cross-browser
testing. Zoom controls use `--fluid-target-min` for the conformance-aware target
floor. A production accessibility sign-off is still pending.
